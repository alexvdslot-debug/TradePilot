## Limitations and release blockers
- The owner authenticated the production TradePilot session. Authenticated release smoke checks follow deployment.
- `TWELVE_DATA_API_KEY` stays on the existing `tradepilot-market-data` Worker. The app uses an internal `MARKET_PROVIDER` service binding with Access JWT verification on both sides. No secret is read, copied or embedded in source/frontend. The prior quote interface is preserved.
- Provider entitlement, delay and exchange-session evidence are unverified. Therefore genuine live rankings and automatically triggered alerts remain disabled, even if historical candles can be obtained.
- Stocktwits app connector authorization does not grant credentials or redistribution rights to a deployed Worker. No unsupported Stocktwits website scraping or fabricated corroboration is implemented.
- No broker API, direct DEGIRO CSV mapping (needs a real example), corporate actions, FIFO/tax reporting, persistent correction/audit history, historical FX performance/consolidated EUR valuation, current portfolio valuation/concentration or transaction-linked win-rate are claimed.
- State is a bounded per-user versioned snapshot (200KB, max2000 events, max500 journal plans, max50 watchlist/alerts). Conflicting tabs receive409 and must reload; no silent merging.
- Quota counters are per isolate, not distributed. Background/push notification dispatch is not deployed. Alert configuration is stored but trigger/delivery is not accepted as complete.
- WebKit automated coverage is not a physical iPhone acceptance test.

## Safe deployment and rollback
Apply only `0003_private_state.sql` to the existing D1 binding. It creates a new table and does not update/delete existing user/settings records. Deploy all Worker modules from the tested tree; retain existing bindings and all secrets. Record prior Worker deployment/version before release. Rollback uses that prior Worker version and leaves the additive table in place; never drop user data to roll back code.

## Lessons
Use true same-origin browser tests with the production security headers. Guard responses from both reads and writes at session boundaries; memory reset alone is not enough to clear already-visible private data. Match browser engines to pinned test dependencies. Safari focus and immediate state reset need browser-specific test actions that do not assume a click leaves a control checked/focused.
